Подборка доступных товаров по рекомендациям с учётом исключений и повторений.

[Полное задание](docs/TASK.md). Работа выполняется в собственной копии репозитория.

## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

src/main/kotlin/lab2/ProductSelection.kt

**Как работает функция и почему выбран такой способ обработки данных?**

Функция создаёт индекс каталога productsById с помощью associateBy, чтобы находить товар по идентификатору без перебора каталога. 
Исключения преобразуются в множество excluded, а идентификаторы добавленных товаров хранятся в множестве addedIds. 
После этого функция один раз проходит по рекомендациям и добавляет подходящие товары в результат. 
Такой способ подходит для большого каталога и большого числа рекомендаций.

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Рекомендации просматриваются последовательно, поэтому товары добавляются в порядке первого появления их идентификаторов. 
Множество addedIds предотвращает повторное добавление товара. 
Исключённые идентификаторы пропускаются, неизвестные отсутствуют в индексе каталога, а недоступные отбрасываются проверкой available.
В результат добавляются исходные объекты Product. 
Входные списки не изменяются. Все вспомогательные коллекции создаются внутри функции, поэтому повторные вызовы независимы.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях.

**Время выполнения:**

В среднем O(p + r + e). 
Построение индекса каталога занимает O(p), создание множества исключений — O(e), просмотр рекомендаций — O(r). 
Оценка предполагает среднюю стоимость поиска и добавления в хеш-таблицах O(1).



**Дополнительная память:**

Без учёта результата — O(p + e + k): индекс каталога занимает O(p), множество исключений — O(e), множество добавленных идентификаторов — O(k). 
Так как k ≤ p, эту оценку можно упростить до O(p + e).
Отдельно список результата занимает O(k). 
Объекты товаров не копируются: в списке хранятся ссылки на исходные объекты.
